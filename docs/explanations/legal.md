# Legal compliance

What the public site owes its visitors and the publishers of the models it
offers, and how the code keeps each claim true. Plan:
[issue #62](https://github.com/bthek1/model_playground/issues/62).

**Not legal advice.** This is a reading of the obligations for a free,
non-commercial, personal project run from Australia, not a lawyer's review. If
the site turns commercial (ads, payments, a company behind it) or the backend
with user accounts goes public, the analysis changes. See [§6](#6-out-of-scope).

---

## 1. What applies, and why so little does

The architecture does most of the work. Inference is local, so nothing a visitor
types, opens, records or films leaves the tab. The static build has no
accounts. Analytics stores nothing on the device (#60). What remains is mostly
**disclosure and attribution**, not consent machinery.

| Area | What applies | How the site meets it |
|---|---|---|
| **Privacy: Australia** (Privacy Act 1988, APPs) | The small-business exemption (under A$3M turnover) almost certainly covers a personal non-commercial site. A notice is good practice regardless. | `/privacy`, written to also satisfy the stricter regime below. |
| **Privacy: GDPR / UK GDPR** | Applies extraterritorially once a site "monitors behaviour" of EU/UK visitors, and analytics counts. IP addresses are personal data. Art. 13 lists what a notice must say. | `/privacy` names the controller, the contact, every recipient and what it gets, the lawful basis (legitimate interests), transfers, retention and rights. |
| **Cookies / device storage** (ePrivacy 5(3), PECR) | Consent is needed only for storage that is not strictly necessary. | **No banner, by design.** Analytics uses `persistence: "memory"`. Every stored item is a choice the visitor made or a download they asked for. `/privacy` lists each one. |
| **US state privacy laws** | Thresholds not met. | n/a |
| **Model licences** | Attribution for permissive licences, and restrictions passed on to the user for the rest. | `MODEL_LICENCES`, the picker line and badge, and `/licences`. |
| **Bundled open source** | MIT, Apache and BSD require their notices to ship with the code. | `dist/THIRD-PARTY-NOTICES.txt`, generated by the build. |
| **AI output** | EU AI Act Art. 50 transparency has applied since 2 Aug 2026. Deployers have a personal, non-professional exemption, and nothing here is high-risk. | `/terms` states it, and every generative page's OUTPUT says the result is machine-made (`OutputPanel generated=`). |
| **Liability** | No warranty is implied without terms. Australian Consumer Law guarantees cannot be excluded. | `/terms`: as-is, limited to what the law allows, ACL rights preserved. |
| **Accessibility** | The European Accessibility Act exempts this site. WCAG 2.2 AA is still the target. | `/accessibility` states the target and the known gaps. |
| **Impressum, DMCA agent** | Neither applies to a non-commercial site that hosts no user content. | A contact address for copyright questions is enough. |

## 2. The rule: a legal claim on screen is asserted by a test

Every list on a legal page is rendered from data the code itself uses. Each
list has a test that fails when the code moves and the list does not.

| Claim | Rendered from | Kept true by |
|---|---|---|
| "These services receive requests" | `src/legal/recipients.ts` | `legal.test.tsx` renders each row. A new host is a new row, and nothing can detect one automatically: add it by hand. |
| "The site stores these items" | `src/legal/storage.ts` | `conventions.test.ts` scans the source for every `localStorage` key, Cache Storage bucket, IndexedDB database and persisted store, and names any that is undisclosed. |
| "This model's licence is X" | `src/model/licences.ts` | `licences.test.ts` checks that every repo every catalogue downloads has a row and that no row is stale. `just fe-e2e-models` checks each row's `hub` against the model card. |
| "Every model is listed" | `src/legal/catalogues.ts` | `conventions.test.ts` names any exported `*_MODELS` / `*_PAIRS` / `*_ENTRIES` array missing from it. |
| "Outputs are machine-made" | `OutputPanel generated=` | `conventions.test.ts` lists the generative routes. |
| "Packages' notices ship" | `scripts/third-party-notices.mjs` | `check:bundle` requires the file and the worker-only packages in it. `legal.spec.ts` fetches it from the built site. |
| "This build sends no analytics" | `ANALYTICS_ENABLED` | `legal.test.tsx` renders `/privacy` under each flag combination. |

The pages gate on the **same build flags** as the behaviour they describe. A
build without `VITE_POSTHOG_KEY` never mentions PostHog, and one without a
backend never mentions accounts. A sentence describing a request the build does
not make is as untrue as the reverse.

## 3. Model licences

`MODEL_LICENCES` is keyed by **Hub repo**, not by catalogue entry. A licence
belongs to the repo. Pairs (`/pose`, `/text-ranking`, `/robotics`) download two
repos. A model offered on two pages (CLIP, OWLv2, Depth Anything) would
otherwise state its licence twice. `entryRepos()` says which repos an entry
fetches, and `entryLicences()` orders them strictest first.

- **A mirror's licence is its upstream's.** Most `Xenova/*` and
  `onnx-community/*` cards declare nothing, and converting weights does not
  change their terms. `from` names the card that does declare one.
- **`hub` is that card's `license:` field, verbatim.** `just fe-e2e-models`
  re-reads it and fails on drift, `null` included, because a card that starts
  declaring a licence invalidates a `via` sentence.
- **Four terms**: `permissive`, `non-commercial`, `custom`, `unstated`. Anything
  but permissive needs a `note` the user can act on. The picker badges the row
  before it is chosen and states the full line once it is.

The audit (2026-10-07) found these restricted entries. All are kept, beside a
permissive default, because the site is non-commercial and the user is told
before anything loads:

| Repo | Terms | Why |
|---|---|---|
| `briaai/RMBG-1.4` | non-commercial | BRIA's CC non-commercial licence (#24) |
| `Xenova/mms-tts-eng` | non-commercial | Meta MMS, CC BY-NC 4.0 |
| `Xenova/segformer-b0-finetuned-ade-512-512` | non-commercial | NVIDIA's SegFormer licence: research or evaluation only |
| `mattmdjaga/segformer_b2_clothes` | non-commercial | A SegFormer fine-tune; the same licence carries over |
| `Xenova/face-parsing` | non-commercial | Its card limits use to research and education |
| `onnx-community/dinov3-…` | custom | Meta's DINOv3 licence |
| `Xenova/mobilebert-uncased-mnli`, `Xenova/distilbert-base-uncased-mnli` | unstated | `typeform` states no licence |

Two catalogues open on a restricted entry: `/segmentation` defaults to
SegFormer-b0. The "default must be permissive" rule is pinned for
`/background-removal` only. Extending it everywhere would mean reordering
`/segmentation`, which is a product decision rather than a compliance fix for a
non-commercial site.

## 4. Third-party notices

`scripts/third-party-notices.mjs` is a Vite plugin. It records the packages
behind every module Rolldown actually **rendered** into an output chunk (not
`package.json`, which lists what tree-shaking removes). It writes
`dist/THIRD-PARTY-NOTICES.txt` with each package's licence and its `LICENSE` /
`NOTICE` files.

- **Workers are separate builds**, and they hold most of the third-party code
  (Transformers.js, ONNX Runtime). So the plugin is registered twice: in
  `plugins` (writes) and in `worker.plugins` (records into a shared set). Vite
  bundles each worker during the main build, before the main build's
  `generateBundle`. `check:bundle` fails if `onnxruntime-web` is missing from
  the file, which is how a broken worker hook would show up.
- **The build fails on a licence off `ALLOWED`** (permissive licences only),
  naming the package. Add to the allowlist deliberately, never to make a build
  pass.

## 5. Facts to keep current

- **`CONTACT_EMAIL`** (`src/legal/site.ts`) is published on every legal page and
  must be a working inbox before the site deploys.
- **`LAST_UPDATED`** changes with any edit a visitor would want to know about.
- **A new host the browser fetches from** (a CDN, a dataset mirror, a font) is
  a new row in `recipients.ts`. Nothing detects this for you.
- **A new dataset** goes in `src/legal/datasets.ts`, unless its own catalogue
  already carries a licence line (tabular and forecast samples do).

## 6. Out of scope

- **The full stack with accounts.** `/privacy` gains an accounts section when
  `BACKEND_ENABLED`. A public deployment of the backend still needs its own plan:
  account deletion and export (GDPR Arts. 15–17), retention, a breach procedure
  and a DPA with the host.
- **Monetisation**, which would bring consumer law, an Impressum and consent for
  ad tech.
- **Datasets with no stated licence** (Cora, PROTEINS, the Transformers.js
  sample media). They are recorded as found, not removed: they are standard
  research benchmarks, used here for teaching. Replacing them is a decision for
  a commercial turn, not a defect today.
